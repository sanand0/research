# Field notes

- 2026-10-16: Created a self-contained, zero-dependency browser sensor dashboard, focusing on mobile Safari and Chromium. A single user gesture initiates motion/orientation permission requests, camera, microphone, location, NFC, wake lock, and ordinary device signals.
- Browser security constraints: BLE/USB/Serial require separate user-triggered choosers. Websites cannot clear stored site permissions; reset stops streams and subscriptions and offers instructions for removing permission grants in browser settings.
- Measurement policy: mark a sensor Live only on a real reading or successful interface interaction; distinguish API absence from denial/no readings; retain all data locally in the page.
- Validation: Extracted inline JavaScript and passed `node --check`. Opened the page in an isolated Chromium browser, verified all 23 cards / 4 groups and no JavaScript errors after Enable / Reset, tested modal and clearing active status. At a 390 px mobile viewport, page width remains 390 px with a single card column. Injected synthetic `devicemotion` and `deviceorientation` events and observed live values for accelerometer, gyro, and tilt. Physical phone permissions and hardware readings were not tested.

- 2026-10-16: Added `draw.html` as a single-file tilt-to-aim, hold-to-ink experience. Selected a relative, anchored orientation mapping instead of double-integrating accelerometer signals (which drift). Smoothed motion, speed-based width and stationary ink pooling, a thumb-friendly press-and-hold control, recalibration, undo/clear/save and direct finger-drawing fallback.
- Verification: Inline JavaScript passed `node --check`; in a 390×844 viewport, simulated device-orientation readings activated motion mode; holding the pen and changing orientation painted 8,163 nontransparent pixels, releasing lifted it, Undo returned to zero. Without events, direct mouse/finger fallback activated after 3.5 seconds and drew 6,212 ink pixels. Save triggered without browser errors; 1100×800 layout also fit without horizontal overflow. Hardware feel and Safari permissions remain to test on actual phones.
- 2026-10-16: Follow-up feedback: cursor was hard to see when idle, bloated while drawing, marks looked uniformly thick, and finger fallback was unwanted. Found reversed `clamp` parameters giving a constant 23px **radius** (46px diameter). Corrected to a speed-dependent 1–11px radius (~16.7px at 15px/s versus ~3.1px at 350px/s); switched to a contrasting fixed 12px coral cursor with white halo (also visible during pressed drawing), updated cursor speed sampling, and removed all canvas direct-drawing handlers and touch fallback states.
- Verification: `node --check` passed. In a 390×844 Chromium smoke test, holding the button while simulating device orientation changed cursor X from 181px to 290px with the button still held, produced ink, and released cleanly. Dragging directly on a fresh canvas produced 0 ink pixels and left Undo disabled. Actual phone ergonomics remain unverified.
