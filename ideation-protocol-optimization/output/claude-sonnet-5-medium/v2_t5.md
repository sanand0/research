# BAN

The reflexive 30-second list for "cut traffic congestion":

1. Congestion pricing / tolls to enter downtown
2. Improve public transit
3. Bike lanes / cycling infrastructure
4. Smart/synchronized traffic signals
5. Remote work / staggered work hours
6. Widen roads / add lanes
7. Carpool (HOV) lanes

**Banned along with disguises:** any variant that (a) prices the *road entry itself*, (b) improves transit vehicles/routes, (c) builds cycling infra, (d) optimizes signal timing/AI-controlled lights, (e) shifts *work* schedules, (f) adds physical road capacity, (g) rewards multi-person cars via lane access.

---

# DIVERGE

**Dimensions:** mechanism (pricing / information / consolidation / elimination / allocation-by-slot) · actor (driver / employer / school / insurer / institution / logistics firm / zoning board) · who pays (driver, institution, taxpayer, insurer) · timing (real-time, daily, seasonal, structural/generational) · what's removed or inverted (the trip, the destination, the queue, ownership of road-time, centralized control).

**Two unrelated domains, atomic rules borrowed:**

*Aviation slot allocation:* (a) scarce time is pre-booked, not FCFS; (b) unused slots are forfeited — "use it or lose it"; (c) slots are tradable/leasable between operators.
*Ant colony foraging:* (a) pheromone trails decay if unused; (b) parallel exploration converges on efficient paths via reinforcement; (c) crowding produces negative feedback that reroutes without central control.

# CONVERGE

**Critiques (assumption / cheapest falsifier / why the obvious list missed it):**

- **S1** Assumption: vehicles can be reliably identified/verified at a slot. Test: pilot one intersection, watch no-show/gaming rate. Missed because pricing is easier to explain politically than allocation.
- **S2** Assumption: enough vehicles run the app for the decaying signal to matter. Test: run it in traffic simulation software against existing crowdsourced data — no deployment needed. Missed because "smart traffic" reads as centralized control (banned), not a decentralized algorithm change to apps people already have.
- **S5** Assumption: traffic can be attributed to a specific institution accurately. Test: use existing mobile-location analytics (already sold to retailers) to estimate one mall's trip attribution. Missed because generalists price the visible actor (driver), not the invisible demand-aggregator (institution).
- **S7** Assumption: school drop-off is a large enough share of the *morning* peak specifically. Test: compare existing traffic-count data on school days vs. school holidays — natural experiment, no pilot needed. Missed because "flexible hours" gets applied to jobs and never to schools, which are actually more rigidly synchronized.
- **S8** Assumption: freight/delivery vehicles are a disproportionate bottleneck cause (double-parking, turning), not just trip volume. Test: NYC's off-hour delivery pilot already exists — check before/after data. Missed because "traffic" is reflexively read as commuters, undercounting the e-commerce delivery surge.
- **S9** Assumption: curb search/double-parking time meaningfully drags corridor speed. Test: measure delivery dwell time vs. corridor speed on one commercial block. Missed because congestion is conflated with moving-vehicle volume, ignoring parked/idling friction.
- **S6** Assumption: polycentric cities actually lower peak congestion rather than just creating several smaller synchronized peaks. Test: compare per-capita peak congestion in monocentric vs. polycentric cities of similar size. Missed because it's structural, decades-long — outside the frame of a "fix congestion" brainstorm.

**Pairwise knockout (abridged):** S2 beats S1 (piggybacks on infrastructure that already exists at scale vs. needing new enforcement tech). S5 beats S4 (root-cause institutional lever vs. a narrow slice of discretionary trips). S8 beats S9 and S7 (already has real-world proof via NYC's off-hour delivery program). Final: **S8 vs. S5** — S5 is more general (a funding/incentive mechanism that could itself finance freight fixes), S8 is narrower but proven. Both survive as complementary practical picks; **S2 and S6** survive as the wildcards — one cheap-to-test-now, one structurally deep.

## Recommendations

**Best practical — Freight curfew + off-peak delivery incentive (S8).** Non-obvious insight: commuters aren't the whole story — e-commerce-driven delivery vehicles cause outsized disruption per vehicle (double-parking, turning, dwell time) at chokepoints. First cheap test: it's already been run — pull NYC DOT's off-hour delivery pilot data and replicate the before/after methodology on your own city's worst freight corridor before building anything new.

**Also practical — Corporate congestion liability (S5).** Non-obvious insight: a stadium, mall, or single-site megaemployer *generates* traffic the way a factory generates pollution, but only the driver is ever billed. Attribution used to be the blocker; it isn't anymore. First cheap test: buy existing mobile-location foot-traffic data for one large venue and see if its trip attribution error margin is small enough to bill on.

**Best wildcard — Decaying pheromone traffic broadcast (S2).** Non-obvious insight: you don't need to control infrastructure to get decentralized self-organization — you need a decay function layered onto routing data that already exists in Waze/Google Maps. First cheap test: run it purely in simulation against a city's existing traffic dataset; if variance in peak congestion drops versus the current static/crowdsourced routing logic, it's worth a real conversation with a nav-app provider.

**Second wildcard — De-annex the destination (S6).** Non-obvious insight: most congestion fixes treat trip origins as fixed and attack the route; this attacks the fact that everyone is going to the *same place at the same time*. First cheap test: a retrospective comparison of peak-congestion-per-capita in polycentric vs. monocentric metro areas of similar population — pure desk research, no pilot required.
