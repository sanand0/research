## FRAME

**Binding constraint:** peak-hour road space is a scarce shared resource handed out free exactly when it's scarcest — nothing else moves until that price/allocation signal moves.

**The mode (banned, plus thin disguises of each):** congestion pricing/toll zones · build more transit · bike lanes · smarter/synced traffic signals · remote work promotion · HOV/carpool lanes · car-free zones.

## DIVERGE

**Dimensions:** mechanism (price/info/space/ownership/norm) · actor (city/employer/insurer/utility/developer/individual) · who pays · timing (before/during/after trip) · what's removed or inverted.

Candidates (typicality score = odds a generic assistant suggests it):
1. Trip-generation "cap-and-trade" permits required for new developments — 0.15
2. City buys back residents' private parking rights for cash — 0.10
3. Freight/delivery companies bid for scheduled logistics windows separate from commuters — 0.30
4. Public shame dashboards showing per-trip time/carbon "receipts" — 0.15
5. Mobile city services (clinics, DMV) travel to neighborhoods instead of citizens traveling in — 0.20
6. Utility bills carry a peak-commute-hour surcharge, syncing road pricing to a bill people already watch — 0.10
7. Restaurant-style "enter now vs wait 15 min" wait-time signage at zone entrances — 0.30
8. City overbooks road-access permits (predicted no-show modeling) and fines/reimburses on deviation — 0.15
9. Find the single keystone bottleneck node and apply one radical fix only there — 0.20
10. Deliberately remove informal slack (shoulder use, lenient ramp metering) to make the true capacity ceiling brutally legible — 0.10

*(Dropped: occupancy-sensored signal priority — too close to HOV, thin disguise.)*

## CONVERGE

Causal paths + load-bearing assumption + cheapest falsification test:

- **#1 zoning cap-and-trade** — X: permit new destinations by predicted trips → Y: development sited to avoid adding peak load. Assumption: developers change siting, not just eat/pass the cost. Test: pilot one district, compare trip-generation/project vs. control district.
- **#6 utility cross-pricing** — X: peak-hour surcharge on utility bill → Y: households reschedule errands using a channel they already optimize around. Assumption: peak-pricing habits transfer across domains. Test: A/B pilot with one utility partner vs. control subdivision.
- **#8 permit overbooking** — X: sell more road permits than capacity, fine/reimburse on deviation → Y: supply self-corrects to real demand, smoothing peak. Assumption: no-show rate is modelable like airline seats. Test: run the model against historical trip data before any real deployment.
- **#9 keystone node** — X: fix only the single dominant bottleneck → Y: disproportionate network-wide unclogging. Assumption: a true dominant keystone exists (vs. diffuse bottlenecks). Test: simulate removing top-1 node vs. top-10 nodes — concentrated gains validate it, diffuse gains kill it.
- **#10 remove slack** — X: end informal overflow leniency → Y: forced permanent rescheduling. Assumption: informal slack is what sustains marginal peak demand. Weak survivability: high backlash risk with no guaranteed behavior shift — knocked out.
- **#2 parking buyback** — modest, opt-in, adverse-selects people who already drive little — knocked out on consequence.
- **#7 wait dashboards** — cheap, low-risk, but marginal-driver-only impact — kept as minor complement, not a finalist.

**Pairwise knockout:** #8 beats #6 (more consequential — directly reallocates the core scarce resource rather than nudging around it) but only because it has a genuinely cheap pre-deployment kill test (simulation against historical data). #6 survives as the safer fallback. #9 beats #10 (same ecological logic, but #9 is testable in simulation with zero deployment risk while #10 risks real-world backlash for uncertain payoff).

## RECOMMENDATION

**Best practical: #8 — permit overbooking with deviation-based fines.** Insight: treat road access like airline seat inventory — sell more peak permits than physical capacity based on predicted no-shows, then use real-time fines/reimbursements to keep actual usage matched to capacity. It's self-correcting rather than a blunt flat toll, and unlike congestion pricing it doesn't require guessing the "right" price up front. First cheap test: run the no-show prediction model against the city's existing historical trip data — if predicted variance is too wide, the mechanism collapses before a single permit is sold.

**Best wildcard: #9 — keystone-node-only intervention.** Insight: most congestion fixes assume the problem is network-wide, but if a city's jams are actually driven by one or two dominant chokepoints, fixing only those could beat any city-wide program at a fraction of the cost. First cheap test: run the existing traffic simulation model comparing "fix top 1 node" vs. "fix top 10 nodes" — if gains concentrate in the top node, this is a very cheap high-leverage move; if gains are diffuse, kill it immediately and don't spend on infrastructure.
